# Labka

Трекер лабораторных работ и домашних заданий для вуза. Преподаватель ведёт курсы, публикует
задания, материалы и объявления, составляет расписание и проверяет работы. Студент видит курсы
своей группы, сдаёт работы, следит за дедлайнами, оценками и занятиями в одном календаре и ведёт
личные задачи. Администратор заводит структуру вуза, группы, студентов и преподавателей.

> **Статус.** Backend (REST API, WebSocket, админка) готов и покрыт тестами. Веб-приложение
> (`frontend/`) реализует все экраны студента и преподавателя и работает как с настоящим backend,
> так и на встроенных демо-данных; снимки экранов — в `docs/screenshots/`.

## Что умеет

- **Роли:** студент, преподаватель, администратор (админка на `/admin`). Регистрируется только студент —
  по коду группы и почте из списка группы; преподавателя создаёт администратор.
- **Курсы:** привязаны к семестру (осенний или весенний), группам, шкале оценок (диапазон или зачёт);
  архив — только чтение.
- **Материалы, объявления, задания** (лабораторные, практики, домашние), дедлайны мягкие и жёсткие,
  файлы в S3-хранилище.
- **Сдача и проверка:** попытки с файлами и комментарием, вердикт «принято» или «на доработку»,
  оценка, очередь на проверку у преподавателя.
- **Расписание и календарь:** пары только в окнах звонков, повтор каждую неделю / по чётным / по нечётным,
  разовые занятия, зачёты и экзамены; календарь на день, неделю и месяц с номером и чётностью недели.
- **Уведомления** в реальном времени по WebSocket и напоминания о дедлайнах за сутки.
- **Главная:** ближайший дедлайн, занятия и курсы; у преподавателя — число работ на проверке.

Подробно: [требования](docs/spec.md), [сценарии](docs/use-cases.md), [экраны](docs/screens.md),
[план разработки](docs/plan.md).

## Состав репозитория

```
backend/    FastAPI-сервис, миграции, тесты, docker-compose backend
docs/       требования, сценарии, экраны, план
frontend/   веб-приложение на React + TypeScript
infra/      docker-compose окружения: Postgres, MinIO, общая сеть labka
```

## Технологии

**Backend:** Python 3.14 · FastAPI · uvicorn · dishka (внедрение зависимостей) · SQLAlchemy 2 (async) + asyncpg ·
Alembic · PostgreSQL 18 · S3 (MinIO локально) · APScheduler · sqladmin · pydantic-settings ·
структурные JSON-логи · pytest, Testcontainers, ruff, mypy · менеджер пакетов `uv`.

**Frontend:** React 19 · TypeScript · Vite · React Router · TanStack Query · shadcn/ui (Radix) +
Tailwind CSS 4 · React Hook Form + Zod · Motion · openapi-fetch (типы из OpenAPI backend) ·
Playwright (снимки экранов).

Зависимости фиксируются в `backend/pyproject.toml` и `backend/uv.lock`, `frontend/package.json` и
`frontend/package-lock.json`.

## Модель данных

| Область | Таблицы |
|---|---|
| Структура вуза | `faculties`, `departments`, `directions`, `groups` |
| Пользователи и вход | `users`, `sessions`, `group_invites` (почты группы для регистрации), `teacher_groups` |
| Курсы | `courses`, `course_groups`, `course_materials` + `course_material_files`, `announcements` |
| Задания и проверка | `assignments` + `assignment_files`, `submissions` + `submission_files`, `reviews` |
| Расписание | `schedule_rules`, `extra_lessons`, `course_exams` |
| Личное и уведомления | `personal_tasks`, `notifications` |

Статус работы студента по заданию и текущая оценка не хранятся: считаются по попыткам и проверкам.
Расписание не хранится сеткой: занятия вычисляются из правил и семестра курса. Схема описана
миграциями Alembic (`backend/alembic/versions`).

## Настройка и запуск

Нужны Docker, [uv](https://docs.astral.sh/uv/) и Python 3.14.

### Backend и окружение (всё в Docker)

Окружение (`infra/`) поднимается отдельно и создаёт Docker-сеть `labka`; backend (а позже frontend)
поднимается своим compose-файлом и подключается к этой сети.

```bash
cd infra
cp .env.example .env                    # пароли Postgres и MinIO — заменить на свои
make up                                 # Postgres, MinIO, сеть labka

cd ../backend
cp config.toml.example config.toml      # настройки приложения; учётки БД и S3 — как в infra/.env
make up                                 # миграции и backend
make create-admin-docker                # создать администратора: спросит почту, ФИО и пароль
```

После запуска:

| Что | Адрес |
|---|---|
| API и документация | http://localhost:8000/docs |
| Админка | http://localhost:8000/admin |
| WebSocket уведомлений | ws://localhost:8000/api/ws |
| Консоль MinIO | http://localhost:9001 |

Остановить: `make down` в `backend/` и `infra/`. Логи: `make logs` там же.

### Логи

Backend пишет структурные JSON-логи в stdout (`make logs`). Каждый ответ API несёт `X-Request-Id`,
он же есть в каждой строке лога этого запроса.

### Backend без Docker

Нужен запущенный PostgreSQL и S3-совместимое хранилище — например, окружение из `infra/`
(`make -C infra up`). В `config.toml` для этого поменять `postgres_host` на `localhost` и `s3.endpoint_url`
на `http://localhost:9000`: по умолчанию там адреса внутри Docker-сети.

```bash
cd backend
uv sync
make upgrade        # применить миграции
make run            # запустить на http://localhost:8000
make create-admin   # создать администратора
```

Приложение запускается с одним воркером: планировщик и реестр WebSocket-соединений живут в
процессе.

### Frontend

Нужен Node.js 22 или новее.

```bash
cd frontend
cp .env.example .env # режим API и лимиты форм
npm install
npm run dev          # http://localhost:5173, демонстрационные данные
```

В `frontend/.env` — режим (`VITE_API_MODE`) и лимиты форм: размер файла и длина пароля. Лимиты
должны совпадать с `backend/config.toml` (`[s3] max_file_size_bytes`, `[auth] password_*_length`):
сервер проверяет их сам, а фронту они нужны для понятной ошибки под полем. Как и backend, без них
приложение не стартует и называет каждую незаполненную настройку. Можно ли сейчас сдать работу,
решает backend: поле `my_progress.can_submit` у задания и в ленте курса.

Демо-вход — кнопки «Студент» и «Преподаватель» на экране входа
(`student@labka.ru` / `teacher@labka.ru`, пароль `labka2026`). Демо-данные живут в памяти вкладки
и собираются заново при перезагрузке; даты считаются от сегодняшнего дня. Чтобы посмотреть
состояния экранов, к адресу можно добавить `?mock=slow` (долгая загрузка), `?mock=error`
(ошибка сервера) или `?mock=empty` (нет данных).

С настоящим backend: `npm run dev:real` (сначала `make up` в `infra/` и `backend/`). Vite проксирует
`/api` и WebSocket `/api/ws` на `http://localhost:8000` (другой адрес — переменная `BACKEND_URL`),
поэтому cookie сессии работают без настройки. В `cors.origins` backend указан `http://localhost:5173`.
Пользователей, группы и курсы создают администратор
(в админке) и преподаватель (в приложении); студент регистрируется сам по коду группы.

Другие команды: `npm run build` (проверка типов и сборка в `dist/`), `npm run lint`,
`npm run api:types` (обновить типы API из `src/shared/api/openapi.json`), `npm run icons`
(пересобрать модуль иконок),
`npm run screenshots` (переснять `docs/screenshots/`, нужен запущенный `npm run dev` или
`npm run dev:real` и Google Chrome; входит как `student@labka.ru` и `teacher@labka.ru` с паролем
`labka2026`, в режиме настоящего API такие пользователи должны существовать).

### Тесты и проверки

```bash
cd backend
make check          # форматирование, линтер, типы
make test           # unit-тесты, без Docker
make test-all       # unit + integration (нужен Docker: PostgreSQL и MinIO в Testcontainers)
```

Каждый тест помечен сценарием из `backend/tests/scenarios.toml`.

## Веб-приложение

### Назначение и сценарии

Одно приложение для двух ролей. **Студент** видит самый срочный дедлайн и ближайшие пары, открывает
курс с лентой заданий и материалами, сдаёт работу файлами и комментарием, следит за статусом и
оценкой, ведёт личные задачи в календаре и получает уведомления. **Преподаватель** создаёт курс и
расписание, публикует задания, материалы и объявления, смотрит, кто что сдал, и проверяет работы из
общей очереди. Администратор работает в админке backend (`/admin`), отдельных экранов у него нет.

### Экраны

| Экран | Адрес | Кто |
|---|---|---|
| Вход, регистрация студента | `/login`, `/register` | гость |
| Главная: ближайший дедлайн или «ждут проверки», занятия, курсы | `/` | все |
| Курс: лента с фильтром, материалы, расписание и экзамены | `/courses/:id` | все |
| Задание: описание, файлы; у студента — сдача и история попыток, у преподавателя — таблица студентов | `/courses/:id/assignments/:id` | все |
| Календарь на неделю и месяц, личные задачи | `/calendar` | все |
| Уведомления | `/notifications` | все |
| Профиль: аватарка, смена пароля, выход | `/profile` | все |
| Архив курсов | `/courses/archive` | все |
| Новый курс, настройки курса (группы, правила расписания, разовые занятия, зачёты и экзамены, архив) | `/courses/new`, `/courses/:id/settings` | преподаватель |
| Создание и правка задания | `/courses/:id/assignments/new`, `…/edit` | преподаватель |
| Очередь на проверку, проверка попытки | `/reviews`, `…/students/:id` | преподаватель |

Подробные макеты — в [docs/screens.md](docs/screens.md), снимки — в
[docs/screenshots/](docs/screenshots/). После входа сверху шапка (меню, логотип, уведомления,
карточка аккаунта), слева навигация со списком курсов, внизу подвал. Кнопка меню сворачивает
навигацию в полосу иконок; на телефоне навигация открывается поверх экрана.

### Структура `frontend/src`

Упрощённый Feature-Sliced Design: слой может импортировать только слои ниже себя.

```
app/        точка входа, провайдеры (TanStack Query, подсказки, тосты), маршруты и их защита по роли, стили и тема
pages/      страницы — собирают экран из виджетов, фич и сущностей
widgets/    крупные блоки: каркас (шапка, навигация, подвал), лента курса
features/   действия пользователя: вход и регистрация, сдача попытки, проверка, редакторы курса,
            задания, материала и объявления, личные задачи, аватарка, смена пароля
entities/   данные предметной области: запросы к API и их маленькие UI (бейджи статуса и типа,
            дедлайн, событие календаря, попытка, аватар)
shared/     API-клиент и типы, демо-backend, утилиты дат и форматирования, валидация,
            UI-компоненты shadcn (`shared/ui`) и общие блоки (`shared/ui/kit`)
```

Типы запросов и ответов генерируются из OpenAPI-схемы backend (`shared/api/schema.d.ts`), так что
поля в коде совпадают с API. Демо-backend (`shared/api/mock`) отвечает на те же пути `/api/...` и
повторяет правила сервера: статусы по попыткам, мягкие и жёсткие дедлайны, блокировку шкалы,
архив, расписание по чётным и нечётным неделям. Переход на настоящий API — переменная
`VITE_API_MODE=real`, код экранов не меняется.

### Интерфейс

- Стиль Google Material 3, только тёмная тема: цвета тёмной схемы Gmail и Google Календаря,
  кнопки-«пилюли», контурные поля, вкладки с полосой, диалоги со скруглением 28 px, подсказки
  и всплывающие сообщения как у Google. Главная и страница курса — в духе Google Classroom:
  карточки курсов с цветной обложкой и быстрыми действиями.
- Сетка с шагом 8 px, одна на все экраны (`shared/ui/kit/page-header.tsx`): колонка 1152 px с полями
  32 (на телефоне 16); шапка страницы — строка крошек 24 px (есть всегда, поэтому заголовок на любой
  странице на одной высоте) и заголовок 32/40; между блоками 32, в секции заголовок → содержимое 16;
  поверхности (списки, таблицы, карточки) — скругление 16, поля 24; кнопки, поля ввода и
  сегментированные кнопки — 40 px, чтобы в одном ряду стояли по одной линии; боковая колонка 320.
  Скелеты загрузки повторяют размеры содержимого, подвал всегда ниже первого экрана, архив и
  настройки в навигации прижаты к низу — при загрузке ничего не сдвигается.
- Иконки — Material Symbols в SVG. Модуль `shared/ui/icons.tsx` собирается скриптом
  `npm run icons` из пакета `@iconify-json/material-symbols`; чтобы добавить иконку, её имя
  дописывают в `scripts/icons.mjs`.
- Файлы показываются с цветной иконкой своего типа (PDF, Word, PowerPoint, таблица, Python, Jupyter,
  C/C++, Java, архив, картинка и т. д.) из Material Icon Theme. Модуль `shared/ui/file-icons.tsx`
  собирает `npm run icons` из пакета `@iconify-json/material-icon-theme`: в сборку попадают только
  нужные иконки; таблица «расширение → иконка» — в `scripts/file-icons.mjs`, незнакомое расширение
  определяется по MIME-типу.
- Шрифт Google Sans, цифры в датах и оценках — табличные.
- Календарь повторяет Google Календарь: виды «День», «Неделя», «Месяц» и «Расписание»,
  шкала времени с линией текущего момента, слева «Создать», мини-календарь и «Мои календари»
  (скрыть занятия, дедлайны, экзамены или задачи), карточка события по клику, клик по пустому
  времени создаёт личную задачу. Горячие клавиши как у Google: T — сегодня, D/W/M/A — вид,
  J/K — вперёд и назад, C — новая задача. На шкале времени — только занятия и экзамены;
  дедлайны и личные задачи (это моменты, а не интервалы) стоят в строке над шкалой со временем.
  У дедлайна видно, что делать: «Сдать», «Доработать», «Просрочено», «На проверке», «Принято»
  (иконка и цвет плашки, расшифровка — в левой панели); в карточке — сколько осталось и правила
  мягкого или жёсткого дедлайна.
- У экранов с данными есть загрузка (скелеты), ошибка с кнопкой «Повторить» и пустое состояние.
- Длинные списки (лента, таблица студентов, очередь, уведомления, архив) — по 20 записей
  с переключением страниц.
- Страницы грузятся отдельными частями при первом переходе; библиотеки вынесены в свои части.
- Формы проверяются на клиенте (Zod) с теми же правилами, что на сервере; ошибки сервера
  показываются под нужным полем.
- Анимации: сворачивание навигации (иконки стоят на месте, сжимается подложка), появление новых
  записей в ленте, истории попыток и уведомлениях, раскрытие полей формы. При
  `prefers-reduced-motion` они отключаются. Страницы сменяются без анимации, как у Google; код
  страниц подгружается заранее, список уведомлений — при наведении на колокольчик.
- Отметка личной задачи «сделано» меняет календарь сразу, без ожидания ответа сервера.
- Адаптивность: от 375 px; на узком экране навигация открывается кнопкой меню, календарь по
  умолчанию показывает день, задача создаётся круглой кнопкой внизу.

### Отличия от макетов

- В календаре есть виды «День» и «Расписание», которых нет в макете экрана 2.4: так устроен
  Google Календарь, на который равняется интерфейс.
- Порт веб-приложения — 5173 (порт Vite по умолчанию). CORS backend настроен на 5173.

## Конфигурация и секреты

Настройки читаются из `backend/config.toml` и переопределяются переменными окружения с разделителем
`__` (например, `DATABASE__POSTGRES_HOST`). Backend в Docker берёт всё из `config.toml`, поэтому
для него там указываются адреса внутри сети: `postgres` и `http://minio:9000`. Секреты окружения (Postgres, MinIO) — в `infra/.env`;
учётки БД и S3 в `backend/config.toml` должны с ними совпадать.
Файлы `.env` и `config.toml` в репозиторий не попадают; примеры без секретов —
`infra/.env.example` и `backend/config.toml.example`. Перед первым запуском замените все
значения `change-me`.

## API

Корень — `/api`; ошибки приходят в формате `{"error": {"code", "message", "details", "request_id"}}`
с подходящим HTTP-статусом. Основные разделы (полный перечень — в `/docs`):

`auth` · `profile` · `home` · `courses` · `materials` · `announcements` · `assignments` · `submissions` ·
`reviews` · `feed` · `schedule` · `calendar` · `personal-tasks` · `exams` ·
`notifications` · `ws` (WebSocket).
