# Labka — frontend

Веб-приложение Labka для студента и преподавателя. Администратор работает в админке backend
(`/admin`), своих экранов во фронте у него нет. Общее описание проекта — в
[корневом README](../README.md).

Своих данных у фронта нет: он работает только с backend.

## Запуск

Нужен Node.js 22 или новее и запущенный backend (см. [README backend](../backend/README.md)).

```bash
make -C ../infra up && make -C ../backend up   # окружение и backend
cp .env.example .env
npm install
npm run dev                                    # http://localhost:5173
```

Vite проксирует `/api` и WebSocket `/api/ws` на `http://localhost:8000` (другой адрес — переменная
`BACKEND_URL`), поэтому приложение и API на одном адресе и cookie сессии работают без настройки
CORS. Пользователей создаёт администратор в админке; студент может зарегистрироваться сам по коду
группы.

## Настройки (`.env`)

| Переменная | Что значит |
|---|---|
| `VITE_MAX_FILE_SIZE_BYTES` | лимит размера файла — как `[s3] max_file_size_bytes` в `backend/config.toml` |
| `VITE_PASSWORD_MIN_LENGTH`, `VITE_PASSWORD_MAX_LENGTH` | длина пароля — как `[auth] password_*_length` |

Лимиты сервер проверяет сам, фронту они нужны, чтобы показать понятную ошибку под полем до
отправки. Без них `vite` не запустится и назовёт незаполненные переменные.

| Команда | Что делает |

## Структура `src/`

Упрощённый [Feature-Sliced Design](https://feature-sliced.design/): слой импортирует только слои
ниже себя, импорты — через алиас `@/`.

```
app/        точка входа, провайдеры (TanStack Query, тосты), маршруты и их защита по роли, стили и тема
pages/      страницы — собирают экран из виджетов, фич и сущностей
widgets/    крупные блоки: каркас приложения (шапка, навигация, подвал), лента курса
features/   действия пользователя: вход и регистрация, сдача и проверка попытки, редакторы курса,
            задания, материала и объявления, личные задачи, аватарка, смена пароля
entities/   сущности предметной области: запросы к API и их маленькие UI (бейджи, дедлайн, попытка…)
shared/     api/ — клиент, типы, WebSocket; lib/ — даты, форматирование, валидация;
            ui/ — компоненты shadcn; ui/kit/ — общие блоки (шапка страницы, список файлов, пагинация…)
```

Маршруты описаны в `app/router.tsx`, страницы загружаются лениво. Перечень экранов — в
[docs/screens.md](../docs/screens.md).

## Работа с API

- Клиент — `openapi-fetch` (`shared/api/client.ts`), данные кэширует TanStack Query. Запросы и
  ключи кэша лежат в `entities/*/api.ts`.
- При истёкшем access-токене клиент один раз обновляет сессию и повторяет запрос.
- Уведомления приходят по WebSocket (`shared/api/live.ts`): при обрыве он переподключается, после
  переподключения список перечитывается.
- Можно ли сейчас сдать работу, решает backend — поле `my_progress.can_submit`; фронт это не
  вычисляет.

### Типы API

Типы запросов и ответов генерируются из OpenAPI-схемы backend, поэтому поля в коде совпадают с
API. После изменения API:

```bash
curl -s http://localhost:8000/openapi.json -o src/shared/api/openapi.json
npm run api:types    # обновит src/shared/api/schema.d.ts
```

`schema.d.ts` руками не правится.

## Интерфейс: договорённости

- Стиль Google Material 3, только тёмная тема; календарь повторяет Google Календарь (виды «День»,
  «Неделя», «Месяц», «Расписание», горячие клавиши T, D/W/M/A, J/K, C).
- Единая сетка с шагом 8 px задана в `shared/ui/kit/page-header.tsx`: колонка 1152 px, поля 32
  (на телефоне 16), отступ между блоками 32, высота кнопок и полей 40.
- У каждого экрана с данными есть три состояния: загрузка (скелеты в размер содержимого), ошибка
  с кнопкой «Повторить» и пустое состояние.
- Длинные списки — по 20 записей с пагинацией.
- Формы проверяются Zod по тем же правилам, что на сервере; ошибки сервера показываются под
  нужным полем.
- Анимации отключаются при `prefers-reduced-motion`.
- Минимальная ширина экрана — 375 px.

### Иконки

Иконки собираются в модули скриптом `npm run icons`, в сборку попадают только используемые:

- интерфейсные — Material Symbols, `shared/ui/icons.tsx`; новую иконку дописать в
  `scripts/icons.mjs`;
- иконки типов файлов — Material Icon Theme, `shared/ui/file-icons.tsx`; таблица
  «расширение → иконка» — в `scripts/file-icons.mjs`, незнакомое расширение определяется по MIME-типу.

Сгенерированные модули руками не правятся.
