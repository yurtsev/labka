# Сценарии

Что делает каждая роль и чем это заканчивается. Номера сценариев (`UC-…`) совпадают с метками тестов
backend: каждый сценарий закрыт тестами из `backend/tests/scenarios.toml`.

Роли:

- **Администратор** работает только в админке backend (`/admin`), в веб-приложение не входит.
- **Преподаватель** ведёт свои курсы. Его аккаунт создаёт администратор.
- **Студент** видит курсы своей группы. Регистрируется сам по коду группы.

## Администратор

| № | Сценарий | Что получается |
|---|---|---|
| UC-A1 | Войти в админку | Пускает только пользователя с ролью «администратор». Первый администратор создаётся командой `make create-admin` |
| UC-A2 | Вести структуру вуза | Подразделения (факультеты и центры), кафедры, направления. Элемент, на который ссылаются, удалить нельзя |
| UC-A3 | Создать группу | Направление, уровень, форма обучения, год набора, номер. Название собирается само (`БВТ2601`), его можно поправить. Код регистрации показывается один раз |
| UC-A4 | Создать группы пачкой | Группы `БВТ2601…БВТ260N`, у каждой свой код. Если хоть одно название занято, не создаётся ни одна |
| UC-A5 | Добавить почты студентов в группу | Списком или из CSV. Итог отдельно называет добавленные, некорректные, повторы и уже занятые почты |
| UC-A6 | Перевыпустить код группы | Старый код перестаёт работать, зарегистрированных студентов это не затрагивает |
| UC-A7 | Создать преподавателя | ФИО, почта, кафедра, прикреплённые группы. Пароль генерируется и показывается один раз с кнопкой «Скопировать» |
| UC-A8 | Перевести студентов в другую группу | Студенты видят курсы новой группы, их прежние попытки остаются |
| UC-A9 | Прикрепить или открепить группы у преподавателя | Только прикреплённые активные группы преподаватель может добавлять в курсы |
| UC-A10 | Сбросить пароль | Новый пароль показывается один раз, все сессии пользователя завершаются. Можно сразу нескольким студентам |
| UC-A11 | Деактивировать пользователя | Вход закрыт, сессии завершены, данные остаются. Можно активировать обратно |
| UC-A12 | Деактивировать группу | По желанию — вместе со студентами. Неактивную группу нельзя добавить в курс, по её коду нельзя зарегистрироваться |

## Студент и преподаватель

| № | Сценарий | Что получается |
|---|---|---|
| UC-C0 | Зарегистрироваться (студент) | Почта, код группы, ФИО, пароль. Код верный, группа активна, почта есть в списке этой группы и ещё не занята — создаётся студент и сразу выполняется вход |
| UC-C1 | Войти | Открывается сессия, в cookie ставятся access- и refresh-токены. Неверная почта и неверный пароль дают одну и ту же ошибку |
| UC-C2 | Продлить сессию | По refresh-токену выдаётся новая пара токенов. Повторное использование старого refresh-токена отзывает сессию |
| UC-C3 | Выйти | Сессия отзывается, WebSocket закрывается |
| UC-C4 | Сменить пароль | Нужен текущий пароль. Остальные сессии завершаются, текущая остаётся |
| UC-C5 | Сменить аватарку | PNG, JPEG, WebP или GIF. Прежний файл удаляется из S3 |
| UC-C6 | Получать уведомления | Пока приложение открыто, уведомления приходят по WebSocket во все вкладки. Остальные ждут в списке |
| UC-C7 | Просмотреть уведомления | Список постранично, фильтр непрочитанных, счётчик, «Прочитать все». Клик ведёт к объекту |
| UC-C8 | Посмотреть календарь | День, неделя, месяц. Занятия, дедлайны, зачёты и экзамены; у студента ещё и личные задачи |

## Преподаватель

| № | Сценарий | Что получается |
|---|---|---|
| UC-T1 | Посмотреть главную | Сколько работ ждут проверки, ближайшие занятия, курсы с числом работ на проверке |
| UC-T2 | Создать курс | Название, описание, семестр, группы (только прикреплённые к нему), шкала по умолчанию, пояснение к оценке. Студенты получают уведомление |
| UC-T3 | Изменить курс | Шкалу курса нельзя поменять, если по заданиям с этой шкалой уже есть попытки. Семестр не меняется |
| UC-T4 | Добавить или убрать группу | Добавленная группа сразу видит курс, убранная перестаёт |
| UC-T5 | Вести материалы | Название, текст в Markdown, файлы. Правка, удаление вместе с файлами |
| UC-T6 | Публиковать объявления | Текст в Markdown в ленте курса, правка и удаление |
| UC-T7 | Создать задание | Тип (лабораторная, практика, домашняя), описание, файлы, дедлайн (без срока, мягкий, жёсткий) по МСК, шкала курса или своя |
| UC-T8 | Изменить задание | Текст, файлы, дедлайн. Шкалу можно менять, пока по заданию нет попыток |
| UC-T9 | Удалить задание | Удаляются и все попытки, и все файлы |
| UC-T10 | Посмотреть, кто что сдал | Таблица студентов: статус, текущая оценка, число попыток, пометка «просрочено». Фильтры по группе и статусу |
| UC-T11 | Проверить попытку | «На доработку» — оценка по желанию, «принято» — оценка обязательна и по шкале задания. Студент получает уведомление |
| UC-T12 | Исправить оценку | Меняются оценка и комментарий, вердикт остаётся |
| UC-T13 | Работать с очередью на проверку | Все непроверенные попытки по своим курсам, старые первыми, фильтры по курсу и заданию |
| UC-T14 | Настроить расписание | Правила: группа, тип занятия, день недели, пара, повтор (каждую неделю, по чётным, по нечётным), аудитория. Плюс разовые занятия |
| UC-T15 | Архивировать курс | Курс уходит из основного списка, читается, но не меняется. Можно вернуть |
| UC-T16 | Назначить зачёт или экзамен | Группа, форма (зачёт, дифф. зачёт, экзамен), дата, пара, аудитория. У группы в курсе один экзамен |

## Студент

| № | Сценарий | Что получается |
|---|---|---|
| UC-S1 | Посмотреть главную | Самый срочный дедлайн и следующие, ближайшие занятия, курсы с числом несданных заданий |
| UC-S2 | Открыть курс | Лента заданий и объявлений со своими статусами и оценками, материалы, расписание. Курсы чужих групп недоступны |
| UC-S3 | Открыть задание | Описание, файлы, дедлайн, свой статус, текущая оценка, история попыток |
| UC-S4 | Сдать работу | Файлы и/или комментарий. Попытка получает статус «на проверке». Преподаватель получает уведомление |
| UC-S5 | Пересдать после доработки | Новая попытка. В очереди у преподавателя остаётся только последняя |
| UC-S6 | Узнать результат | Вердикт, оценка и комментарий в истории попыток. Текущая оценка — из последней проверки с оценкой |
| UC-S7 | Вести личные задачи | Название, дата, время по желанию; отметка «сделано». Видит только сам студент |

Когда сдать работу нельзя:

- пустая попытка — без файлов и без комментария;
- работа уже принята или курс в архиве;
- жёсткий дедлайн прошёл, а до него попыток не было. Если первая попытка была до срока и работу
  вернули на доработку, пересдать можно.

Попытка после мягкого дедлайна принимается, но помечается «просрочено». Можно ли сдать прямо сейчас,
решает backend и отдаёт в поле `my_progress.can_submit`.

## Система

| № | Сценарий | Что получается |
|---|---|---|
| UC-SYS1 | Напомнить о дедлайне | Раз в 5 минут ищутся задания со сроком в ближайшие 24 часа в неархивных курсах. Каждый студент, который ещё не сдавал, получает напоминание один раз; после переноса срока — снова |

Уведомления создаются о новом курсе, задании, материале и объявлении, об изменении задания и
расписания, о назначении и изменении экзамена, о проверке и исправлении оценки (студентам) и о новой
попытке (преподавателю). Неактивные студенты и архивные курсы уведомлений не получают.
