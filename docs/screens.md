# Labka — экраны

Что находится на каждом экране, какие на нём действия и куда с него можно перейти. Правила и модель данных описаны в [spec.md](spec.md), сценарии — в [use-cases.md](use-cases.md).

Время везде показывается по МСК.

## 0. Общая раскладка

После входа у студента и преподавателя одна и та же раскладка:

```
┌────────────────┬─────────────────────────────────────────────┐
│ [аватар]       │                                             │
│ Иванов И.И.    │                                             │
│ ИВТ-21         │                                             │
│                │                                             │
│ ┌ Октябрь ───┐ │            содержимое экрана                │
│ │ пн вт ср … │ │                                             │
│ │  •  ·   •  │ │                                             │
│ └────────────┘ │                                             │
│                │                                             │
│ Главная        │                                             │
│ Календарь      │                                             │
│ Проверка (N)   │  ← только у преподавателя                   │
│ 🔔 Уведомления │                                             │
└────────────────┴─────────────────────────────────────────────┘
```

**Боковая панель:**
- Аватар, ФИО и группа (у преподавателя — кафедра). Клик → профиль.
- Мини-календарь на текущий месяц. Дни с занятиями и дедлайнами отмечены точками. Клик по дню или по календарю → большой календарь на этой дате.
- Навигация: главная, календарь, у преподавателя очередь на проверку со счётчиком.
- Колокольчик со счётчиком непрочитанных уведомлений. Новые уведомления приходят по WebSocket: счётчик растёт, появляется всплывающая подсказка.

## 1. Вход и регистрация

### 1.1. Вход
- Поля: email, пароль. Кнопка «Войти».
- Ошибки: «Неверный email или пароль», «Аккаунт деактивирован».
- Ссылка «Регистрация студента» → регистрация.
- После входа → главная.

### 1.2. Регистрация студента
- Поля: email, код группы, ФИО, пароль, повтор пароля.
- Клиентская валидация: формат email, совпадение паролей, минимальная длина пароля.
- Ошибки: «Неверный код группы», «Этой почты нет в списке группы», «Аккаунт с этой почтой уже зарегистрирован».
- Под формой подпись: «Код группы выдаёт администратор. Преподавателям аккаунт создаёт администратор».
- После регистрации → главная (вход выполняется сразу).

## 2. Экраны студента

### 2.1. Главная

```
┌─────────────────────────────────────────────┐
│ ⏰ БЛИЖАЙШИЙ ДЕДЛАЙН                          │
│ Лаба · «Сортировки» · Алгоритмы              │
│ Петров П.П. · жёсткий · через 2 дня  [→]     │
├──────────────────────┬──────────────────────┤
│ БЛИЖАЙШИЕ ЗАНЯТИЯ    │ БЛИЖАЙШИЕ ДЕДЛАЙНЫ   │
│ Вт 10:30 Лаба Алгор. │ 15.10 ПЗ Рекурсия    │
│ Ср 12:10 ПЗ  БД      │ 18.10 ДЗ Индексы     │
│ Чт 08:30 Лаба Сети   │ 20.10 Лаба Графы     │
├──────────────────────┴──────────────────────┤
│ МОИ КУРСЫ                                    │
│ [Алгоритмы] [Базы данных] [Сети] [ОС]        │
└─────────────────────────────────────────────┘
```

- **Ближайший дедлайн** — ближайшее по сроку несданное задание: тип, название, курс, преподаватель, тип дедлайна, сколько осталось. Клик → задание. Если таких заданий нет: «Все работы сданы 🎉».
- **Ближайшие занятия** (3) — дата, время, тип, курс, аудитория. Клик → календарь на этом дне.
- **Ближайшие дедлайны** (3, следующие после ближайшего) — дата, тип, название. Клик → задание.
- **Мои курсы** — карточки неархивных курсов: название, преподаватель, сколько заданий не сдано. Клик → курс. Внизу ссылка «Архив» → список архивных курсов.
- Пустое состояние (группа ещё не добавлена ни в один курс): «Вас пока не добавили ни в один курс».

### 2.2. Курс

```
┌───────────────────────────────────────────────────────────┐
│ Алгоритмы · Петров П.П.                                    │
│ Шкала: 2–5 · «Оценка = код + защита»                       │
├───────────────────────────────────────────────────────────┤
│ 📚 МАТЕРИАЛЫ                                               │
│   Учебник — Учебник.pdf                                    │
│   Оформление отчётов — текст, ссылка, Методичка.docx       │
├───────────────────────────────────────────────────────────┤
│ ЛЕНТА                     [Все] [Лабы] [ПЗ] [ДЗ]           │
│ 📢 10.10 «Пара в четверг переносится на 12:10»             │
│ [Лаба] Сортировки        до 12.10 жёсткий   ✅ 5           │
│ [ПЗ]   Рекурсия          до 15.10 мягкий    🔁 4, доработка │
│ [ДЗ]   Индексы           до 18.10 мягкий    ⏳ на проверке  │
│ [Лаба] Графы             без дедлайна       — не сдано     │
└───────────────────────────────────────────────────────────┘
```

- **Шапка:** название, преподаватель, шкала по умолчанию и пояснение к оценке.
- **Материалы:** список материалов: название, текст со ссылками, файлы (клик → скачать).
- **Лента:** задания и объявления, новые сверху. Фильтр по типу задания.
  - У задания: тип, название, дедлайн и его тип, мой статус и текущая оценка. Клик → задание.
  - У объявления: дата и текст.
- Архивный курс: сверху плашка «Курс в архиве», всё только для чтения.

### 2.3. Задание

```
┌───────────────────────────────────────────────────────────┐
│ [Лаба] Сортировки · Алгоритмы                              │
│ Дедлайн: 12.10 23:59 МСК (жёсткий) · Шкала 2–5             │
│ Критерии: «3 — работает, 4 — + тесты, 5 — + защита»        │
│ Описание (markdown)…                                       │
│ 📎 Указания_к_лабе_3.pdf                                    │
├───────────────────────────────────────────────────────────┤
│ МОЯ СДАЧА · статус: на доработку · оценка: 4               │
│ [Файлы…] [Комментарий…]                  [Отправить]       │
│ История:                                                   │
│  #2 10.10 — 🔁 4 · «Нет тестов»                            │
│  #1 08.10 — 🔁 — · «Не компилируется»                      │
└───────────────────────────────────────────────────────────┘
```

- **Верх:** тип, название, курс, дедлайн по МСК и его тип, шкала, критерии, описание, файлы преподавателя.
- **Моя сдача:**
  - текущий статус и текущая оценка;
  - форма: файлы (несколько, до 20 МБ каждый) и комментарий, оба поля необязательны, но пустую попытку отправить нельзя;
  - кнопка «Отправить»;
  - история попыток, новые сверху: номер, дата, пометка «просрочено», файлы, комментарий студента, вердикт, оценка, комментарий преподавателя.
- **Когда форма недоступна:**
  - жёсткий дедлайн прошёл, а попыток до дедлайна не было: «Срок сдачи истёк»;
  - работа принята: «Работа принята»;
  - курс в архиве.
- Мягкий дедлайн прошёл: форма доступна, рядом предупреждение «Попытка будет отмечена как просроченная».

### 2.4. Календарь

```
┌───────────────────────────────────────────────────────────┐
│ ◀ 13–19 октября ▶         [Неделя] [Месяц]   [+ Задача]   │
├────────┬────────┬────────┬────────┬────────┬──────┬───────┤
│ Пн     │ Вт     │ Ср     │ Чт     │ Пт     │ Сб   │ Вс    │
│        │ 10:30  │ 12:10  │ 08:30  │        │      │       │
│        │ Лаба   │ ПЗ БД  │ Лаба   │        │      │       │
│        │ Алгор. │        │ Сети   │        │      │       │
│        │        │ ⏰ ПЗ  │        │ ☐ нач. │      │       │
│        │        │ Рекур. │        │ графы  │      │       │
└────────┴────────┴────────┴────────┴────────┴──────┴───────┘
```

- Переключение «неделя / месяц» и стрелки по периодам; показывается номер и чётность недели.
- Три вида событий, у каждого свой цвет:
  - **Занятие:** время, тип, курс, аудитория. Клик → карточка с подробностями и ссылкой на курс.
  - **Дедлайн:** время, тип и название задания. Клик → задание.
  - **Личная задача:** галочка «сделано» и название. Клик → редактирование (название, дата, время) и удаление.
- «+ Задача» или клик по пустому месту в дне → создание личной задачи на этот день.

### 2.5. Уведомления

- Список уведомлений, новые сверху: иконка события, текст, курс, время. Непрочитанные выделены.
- Клик → переход к объекту (задание, курс, календарь) и отметка «прочитано».
- Кнопка «Прочитать все».

### 2.6. Профиль

- ФИО, группа, email (только просмотр).
- Аватарка: загрузить или заменить.
- Смена пароля: текущий пароль, новый, повтор. После смены все остальные сессии завершаются.
- Кнопка «Выйти».

## 3. Экраны преподавателя

### 3.1. Главная

```
┌─────────────────────────────────────────────┐
│ 📥 ЖДУТ ПРОВЕРКИ: 7                  [→]     │
├─────────────────────────────────────────────┤
│ БЛИЖАЙШИЕ ЗАНЯТИЯ                            │
│ Вт 10:30 Лаба Алгоритмы  ИВТ-21  ауд. 305    │
│ Вт 12:10 Лаба Алгоритмы  ИВТ-22  ауд. 305    │
│ Ср 08:30 ПЗ   Базы данных ИВТ-21 ауд. 112    │
├─────────────────────────────────────────────┤
│ МОИ КУРСЫ                    [+ Новый курс]  │
│ [Алгоритмы · 3 на проверке] [БД] [Сети]      │
└─────────────────────────────────────────────┘
```

- **Ждут проверки:** число непроверенных попыток по всем курсам. Клик → очередь на проверку.
- **Ближайшие занятия** (3): дата, время, тип, курс, группа, аудитория.
- **Мои курсы:** карточки (название, группы, сколько попыток ждут проверки), кнопка «+ Новый курс», внизу ссылка «Архив».

### 3.2. Создание курса

- Поля: название, описание, группы (выбор из прикреплённых к преподавателю), шкала по умолчанию (`range` с полями min/max или `binary`), пояснение к оценке.
- После создания → экран курса.

### 3.3. Курс

То же, что у студента (2.2), плюс:

- Кнопка «⚙ Настройки» → настройки курса.
- В материалах: «+ Материал»; у материала — правка названия и текста, «+ Файл», удаление файлов и всего материала.
- В ленте: «+ Задание», «+ Объявление»; объявления можно редактировать и удалять.
- У задания вместо личного статуса показывается сводка: «сдали 14/25 · ждут проверки 3 · приняты 9».
- В шапке курса видны группы.

### 3.4. Настройки курса

- Название, описание, пояснение к оценке.
- Шкала по умолчанию.
- Группы: добавить (из прикреплённых к преподавателю) или убрать.
- **Правила расписания:** таблица — группа, тип занятия, день недели, время начала и конца, повтор (каждую неделю / чётные / нечётные), аудитория. Правила можно добавлять, изменять и удалять.
- Кнопка «Отправить в архив» / «Вернуть из архива».

### 3.5. Создание и редактирование задания

- Поля:
  - тип: лаба / ПЗ / ДЗ;
  - название;
  - описание (markdown, с предпросмотром);
  - файлы;
  - тип дедлайна: без дедлайна / мягкий / жёсткий; для мягкого и жёсткого — дата и время по МСК;
  - шкала: «как в курсе» или своя;
  - пояснение к оценке.
- Если по заданию уже есть попытки, шкала заблокирована, рядом подсказка почему.
- В режиме редактирования есть кнопка «Удалить» с подтверждением «Будут удалены все попытки студентов (N)».

### 3.6. Задание

То же, что у студента (2.3), плюс кнопка «✎ Изменить». Вместо блока «Моя сдача» — таблица студентов:

```
┌──────────────────────────────────────────────────────────┐
│ Группа: [Все ▾]   Статус: [Все ▾]                        │
├──────────────────┬────────┬───────────────┬───────┬──────┤
│ Студент          │ Группа │ Статус        │ Оценка│Попыт.│
│ Иванов И.И.      │ ИВТ-21 │ ⏳ на проверке │ 4     │ 2    │
│ Петрова А.А.     │ ИВТ-21 │ ✅ принято     │ 5     │ 1    │
│ Сидоров С.С.     │ ИВТ-22 │ — не сдано    │ —     │ 0    │
└──────────────────┴────────┴───────────────┴───────┴──────┘
```

- Фильтры по группе и статусу.
- У просроченных попыток пометка.
- Клик по студенту → проверка.

### 3.7. Проверка

```
┌──────────────────┬──────────────────────────────────────┐
│ Иванов И.И.      │ Попытка #2 · 10.10 14:22             │
│ Лаба «Сортировки»│ 📎 main.py  📎 report.pdf             │
│                  │ Комментарий студента: «Добавил тесты»│
│ ПОПЫТКИ          ├──────────────────────────────────────┤
│ ▸ #2 10.10  ⏳   │ Вердикт: (•) Принято ( ) Доработка   │
│   #1 08.10  🔁   │ Оценка:  [ 5 ]  (2–5)                │
│                  │ Комментарий: [……………………]             │
│                  │ [Сохранить]   [Следующая в очереди →]│
└──────────────────┴──────────────────────────────────────┘
```

- Слева: студент, задание, список попыток со статусами.
- Справа: выбранная попытка — дата, пометка «просрочено», файлы (скачать), комментарий студента.
- Форма проверки:
  - вердикт: принято / на доработку;
  - оценка: число в диапазоне шкалы или переключатель «зачёт / незачёт»; обязательна при «принято», необязательна при «на доработку»;
  - комментарий (markdown);
  - «Сохранить» и «Следующая в очереди →».
- У уже проверенной попытки можно исправить оценку и комментарий.

### 3.8. Очередь на проверку

- Все непроверенные попытки по всем курсам, старые сверху.
- Колонки: студент, группа, курс, задание, номер попытки, дата отправки, пометка «просрочено».
- Фильтры по курсу и заданию.
- Клик → проверка.

### 3.9. Календарь

Как у студента (2.4), но:
- занятия по всем курсам преподавателя (с группой);
- дедлайны по его заданиям;
- личных задач нет.

### 3.10. Уведомления

Как у студента (2.5).

### 3.11. Профиль

Как у студента (2.6), вместо группы — кафедра.

## 4. Админка (`sqladmin`)

- **Вход:** email и пароль, только для роли `admin`.
- **Подразделения, кафедры, направления:** списки, создание, редактирование.
- **Группы:**
  - список с фильтрами: подразделение, направление, уровень, форма, курс, активна; поиск по названию;
  - создание одной группы: направление, уровень, форма, год набора, номер → название подставляется автоматически, его можно исправить;
  - создание пачкой: направление, уровень, форма, год набора, количество → `БВТ2601…БВТ2604`;
  - деактивация с вопросом «Деактивировать студентов группы?», активация обратно.
- **Карточка группы:**
  - код регистрации (показать, скопировать, перевыпустить);
  - список почт: добавить списком (по одной на строку) или из CSV, убрать, перенести в другую группу; рядом с каждой почтой — зарегистрирован студент или нет; некорректные и повторяющиеся строки показываются отдельно;
  - студенты группы.
- **Студенты:** список с фильтрами по группе и активности, поиск по ФИО и email; массовые действия — перевести в группу, деактивировать / активировать, сбросить пароль.
- **Преподаватели:** список, создание (ФИО, email, кафедра) → страница со сгенерированным паролем и кнопкой «Скопировать»; в карточке — прикреплённые группы (добавить / убрать); деактивация.
- **Сброс пароля** (студенту или преподавателю) → новый пароль на такой же странице, все сессии пользователя завершаются.
